Scope

ClickSafe Content Agent is a content-production and publishing API client for the ClickSafe Daily workflow. It integrates with authorized platform APIs, including YouTube API Services and a TikTok Login Kit and Content Posting API Sandbox integration.

Google and YouTube data accessed

After Google OAuth authorization, the client may access:

  • authorized YouTube channel identity, including channel ID and channel title;
  • video IDs, titles, descriptions, status/visibility and upload metadata needed to upload or verify content;
  • channel/video analytics used by the client, such as views, estimated watch time, average view duration, average viewed percentage, likes, comments, shares and subscriber gains/losses;
  • OAuth authorization tokens required to perform authorized API operations.

TikTok data accessed

When an authorized TikTok target user completes Login Kit authorization, the client may access only the scopes granted by that user. For the current Sandbox integration these include:

  • basic TikTok account information allowed by user.info.basic, such as the account's open ID, display name and avatar;
  • OAuth authorization data needed to obtain and refresh server-side access tokens;
  • creator information required by the Content Posting API, including current creator username/nickname, available privacy options, interaction availability and maximum supported post duration;
  • posting authorization under video.publish only after the user grants that scope and confirms the applicable post choices.

The client does not request the user's TikTok password. TikTok login is handled by TikTok.

How data is used

  • Confirm that API operations target the account that actually authorized the client.
  • Upload or publish owner-authorized video content and metadata.
  • Query current creator capabilities before TikTok posting so the UI can respect available privacy and interaction options.
  • Measure YouTube performance and support future topic selection from an approved content plan.
  • Maintain limited operational history needed to prevent duplicate releases and audit automation behavior.

Authorized platform data is not sold and is not used for advertising or unrelated user profiling.

Storage and security

OAuth client secrets, access tokens and refresh tokens are not embedded in the public website or browser-side JavaScript. Secret-bearing values are handled in protected server-side automation such as GitHub Actions secrets. Authorization codes are treated as short-lived credentials and are not intentionally exposed in application logs. Transport to platform APIs uses HTTPS.

Third parties

The client communicates with the authorized platform providers required to deliver its features, including Google/YouTube and TikTok. Platform providers process information under their own privacy policies and terms. Production-media services may separately process non-account content inputs where needed for content generation, rendering or publishing.

Revocation and deletion

Users can revoke platform authorization using the relevant account or app-permission controls. After authorization is revoked, stored OAuth credentials for that integration can be deleted from the protected server-side secret store. Locally generated token files, short-lived authorization material, analytics snapshots and operational artifacts can also be deleted when no longer required.

For the current TikTok Sandbox integration, removing the target user's authorization stops future API calls that depend on that authorization.

Consent and control

TikTok users may grant only a subset of requested scopes and may revoke access later. Before a TikTok Direct Post request, the client is designed to use current creator information, expose the available privacy and interaction choices, and require explicit confirmation for that post. The integration must stop if a required authorization or policy gate cannot be verified.
